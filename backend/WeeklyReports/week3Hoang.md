## 2. Layer-by-Layer Updates

### **A. Security Layer (The Core)**
*   **What:** Implemented Spring Security with JWT (JSON Web Tokens).
*   **Where:** `com.vgu.tripify.security`
*   **Why:** To ensure that our API is protected and that we can identify users without maintaining a "session" on the server. This is essential for scalability.
*   **Key Components:**
    *   `SecurityConfig`: The brain of our security. It defines which endpoints are public (`/api/auth/**`) and which require a login. It also disables CSRF (since we are stateless) and sets the session policy to `STATELESS`.
    *   `JwtTokenProvider`: Handles the lifecycle of a token—generating it after login, signing it with a secret key, and extracting user information (like email and roles) for validation.
    *   `JwtAuthenticationFilter`: A custom "gatekeeper" that intercepts every incoming request. It looks for the `Authorization: Bearer <token>` header, validates it, and tells Spring "this user is who they say they are."

## 3. Key Learnings & Concepts

### **Spring Security**
I learned that Spring Security works as a **Filter Chain**. Every request passes through a series of "filters" before reaching our Controller. By adding our `JwtAuthenticationFilter` to this chain, we can decide exactly when and how to verify a user's identity.

### **JWT (JSON Web Tokens)**
JWTs are an amazing way to handle authentication in modern apps. Instead of the server remembering who is logged in (Stateful), the server gives the user a signed "pass" (Stateless).
*   **Header:** Specifies the algorithm (HS256).
*   **Payload:** Contains "Claims" (like user email and their Role).
*   **Signature:** Ensures the token hasn't been tampered with. If even one character is changed, the server will reject it because the signature won't match our secret key.

### **Password Hashing (BCrypt)**
A major takeaway was: **Never store plain-text passwords.** Even if our database is compromised, the hackers only see "hashes" (garbled text) that are computationally impossible to reverse.
